# AP PARTNERS · 에이피파트너 — 홍보 사이트 + 관리자 페이지

프랜차이즈 양도양수 홍보 사이트의 정적 사이트입니다. 등록 점포 12곳(고유번호 AP-001 ~ AP-012)은 실제 현장 실사를 마친 매장입니다.
빌드 도구 없이 `index.html` 하나로 열리며, GitHub Pages · Vercel 같은 정적 호스팅에 그대로 올릴 수 있습니다.

## 물건표 접수 · 중복 등록 규칙 (v13, 2026-11-26)

물건표를 사이트에 올릴 때는 **담당 컨설턴트 + 비공개 지점명**으로 같은 매장인지 먼저 확인합니다. 비교는 공백을 모두 지우고 대소문자를 무시합니다(`○○대점` == `○○대 점`).

| 상황 | 사이트 처리 |
| --- | --- |
| **같은 담당 컨설턴트 + 같은 비공개 지점명** | 새 번호로 중복 등록하지 않고 **기존 `AP-xxx` 매물의 내용·수치만 업데이트** (번호 유지) |
| **다른 컨설턴트 + 같은 비공개 지점명** | 담당자가 다르므로 **별도 신규 매물(`AP-xxx`)로 등록** — 중복 체크는 각 컨설턴트 DB 안에서만 한다 |
| 같은 지점명이라도 블로그·SNS | 사이트 중복과 무관하게 **신규 발행 가능** |

* **단건 등록(`+ 새 매장 등록`)**: 고유번호가 자동으로 붙은 상태(직접 고치지 않음)에서 비공개 지점명을 적으면, 같은 담당 컨설턴트 안에 같은 지점명이 있을 때
  `이미 [AP-001 · ○○점] 매장이 있습니다. 새 번호로 등록하지 않고 기존 매장을 최신 내용으로 업데이트할까요?` 확인창이 뜹니다.
  **확인** → 기존 `AP-xxx` 번호·상태·작성자를 유지한 채 내용·수치·지점명만 최신으로 저장, **취소** → 등록을 중단합니다.
  같은 지점명으로 정말 새 번호를 따로 만들어야 할 때만 `고유번호` 칸에 원하는 번호를 직접 적으면 신규로 등록됩니다.
* **CSV 일괄 등록**: `비공개지점명` 열(선택, 17번째 열)을 추가했습니다. 행에 지점명이 있으면 같은 담당자 안의 기존 매장을 찾아
  새 번호를 붙이지 않고 그 `AP-xxx`를 업데이트하며, 미리보기 상태는 `신규` / `업데이트` / `같은 파일 통합`으로 나뉘고
  요약에 **`신규 N건 · 업데이트 M건`** 이 표시됩니다. 열이 비어 있으면 예전처럼 신규로 등록됩니다.
  한 파일 안에서 같은 지점명이 두 번 나오면 마지막 행 내용으로 합칩니다.
* 업데이트해도 기존 매장의 `id`·`AP-xxx` 번호·노출 상태·`registered_by`(최초 작성자)·비공개 메모는 그대로 두고, `updated_by`에 이번에 올린 사람을 기록합니다.

## 매물 고유번호 (No. AP-001 ~)

모든 점포에는 사람이 부르는 공개 번호가 붙습니다. 내부 키(`id`, `ap-005`)와 달리 상담·문자·비교에서 그대로 통하는 번호입니다.

* 데이터: `data/listings.json`의 각 점포에 `"code": "AP-005"`. `app.js`의 `FALLBACK`도 같은 값을 가짐.
* 표시: 점포 카드·상세 모달·비교표·비교 칩·AI 매칭 결과·상담 접수 화면에 `No. AP-005` 형태로 나옴.
* 검색: 검색창에 `AP-005`·`ap5`·`005` 중 무엇을 적어도 그 점포로 좁혀집니다.
* 알림: 텔레그램·문자에 실리는 점포 표기는 `[AP-005] 우지커피 · 서울 서초구 주거상권`이고, 페이로드에는 `store.code`·`store_codes`가 함께 들어갑니다(상세·비교·AI 매칭 모두).
* 텔레그램 페이로드의 `stores` 항목에는 **관리자 페이지에서 바로 열리는 링크**가 붙습니다: `[AP-005] 우지커피 · 서울 서초구 주거상권 (https://apchangup.com/admin.html?id=AP-005)`. 링크만 따로 담은 `store_links` 배열과 `store.url`도 같은 관리자 링크입니다. 화면·문자·복사/공유에는 링크 없이 `storeLabel` 표기만 쓰고, 손님용 `?id=AP-005` 딥링크는 그대로 유지합니다.
* 링크 열기: 손님 사이트에서 `?id=AP-005` · `?id=ap-005` · `#AP-005`로 들어오면 그 매물(`code`/`id` 매칭)의 **상세 모달을 자동으로 엽니다**. 거래완료·비노출 매물은 열리지 않습니다. 관리자 페이지에서는 `admin.html?id=AP-005`(또는 `#AP-005`)로 들어오면 **매장 DB의 그 카드로 스크롤하며 강조**하고, 로그인 전이면 로그인 직후에 엽니다.
* 관리자: 등록 폼의 **고유번호** 칸은 비워 두면 다음 번호가 자동 제안됩니다. 이미 쓰는 번호는 저장되지 않고, CSV 일괄 등록에서 번호를 비우면 빈 번호가 자동으로 붙습니다.

## 2단계 손님 DB 흐름

| 단계 | 내용 |
| --- | --- |
| **1단계 · 무료** | 상단 검색·필터, 점포 카드 목록, 카드의 초기 인수 비용·월 매출·예상 순수익은 연락처 없이 열람 |
| **2단계 · 4항목** | ① 희망 업종/브랜드(칩+직접 입력) ② 희망 지역(칩) ③ 가용 예산(칩) ④ 연락처(휴대폰 + 동의) 입력 후 잠금 해제 |

게이트가 열리는 지점은 두 곳입니다.

1. 내 조건 매장 찾기의 **`AI 맞춤 매칭 결과 확인`** — 결과 카드는 지역·업종만 보이는 잠금 미리보기로 보이고, 4항목 입력 후 매칭 이유와 상세 요약이 열립니다.
2. 점포 상세 모달의 **`상세 지출·비공개 매물 더 보기`** — 항목별 지출(재료비 % · 인건비·고정비·기타잡비 금액), 확인 포인트, 같은 상권 비공개 매물이 열립니다.

한 번 입력하면 `localStorage`(기기에 저장)와 `sessionStorage`(탭 세션)에 남아 다시 묻지 않습니다.
목록 위 **`4항목 입력 완료 · 잠금 해제됨`** 줄에서 저장된 페이로드를 보거나 `다시 입력`으로 초기화할 수 있습니다.

## 운영 계획으로 묻기 (오토 · 직접 운영)

점포 카드·비교표·관리자 화면에는 운영 방식을 표시하지 않습니다. 대신 손님이 내 조건 매장 찾기에
`풀오토 추천`, `오토로 돌릴 만한 카페`, `직접 운영할 매장`처럼 물으면,
매출 규모 · 인건비 비중 · 매장 규모/특징을 보고 그 계획이 통할 점포를 골라
추천 사유(예: "매출 규모와 인건비 여력이 있어 매니저 체제 검토에 적합")와 함께 보여줍니다.

## 관심 점포 비교 담기 (최대 3곳)

* 점포 카드 오른쪽 **`비교 담기`** → 하단 비교 바에 담깁니다(최대 3곳, 4번째는 안내 후 막힘).
* **`나란히 비교`** 모달에서 초기 인수 비용 · 월 평균 매출 · 예상 순수익 · 상권·위치 · 매장 규모 · 확인할 점을 나란히 봅니다. 비용 최저·수익 최고 항목에는 표시가 붙습니다.
* **`선택한 점포 한 번에 상담 신청`** → 4항목 게이트로 이어지고, 접수 후 선택한 점포 목록과 함께 상담 접수 화면이 열립니다. `source: "compare"`로 손님 DB에 저장됩니다.

## 내 매장 양도 접수

* 2026-11-28부터 헤더(데스크톱) · 히어로 · 빠른 조건 줄 · 상담 섹션 · 모바일 하단 바의 양도 버튼이 모두 **페이지 하단 `#apply` 폼의 `내 매장 매각(양도)` 모드**로 스크롤·전환됩니다(물건표 항목을 빠짐없이 받기 위해 한 경로로 통일).
* 입력: 이름, 브랜드/업종, 지역·지점명, 오픈 시기(선택), 실평수, 층수, 월 매출 / 점포 예치금, 월 임차료, 관리비, 희망 시설·영업권 / 월 순수익, 인건비, 재료비(%), 공과금 / 배달비·기타비용(선택) + **운영·시설(선택)** 영업시간·계약 기간·부가세·주차·시설 상태·최근 월별 매출 + 양도 사유·희망 시기·시설 특이사항(선택) + 연락처·동의. 해당 없는 금액 칸은 0으로 적습니다.
* 접수번호와 함께 사이트(Apps Script `doPost`)를 거쳐 **비공개 Google Drive `ap-waitlist-sells.json`**에 저장되고, 텔레그램 알림도 함께 갑니다. 관리자 **양도 의뢰** 탭이 `getSell`로 Drive의 모든 접수를 불러와 보여 주고, 카드의 `접수 삭제`가 `deleteSell`로 Drive 원본까지 지웁니다. 브라우저 `apPartnerSellRequests`는 Drive에 닿지 못할 때의 예비 사본입니다.
* 기존 팝업 양도 의뢰 모달(`#sellModal`)은 코드에 남아 있지만 지금은 여는 버튼이 없습니다(되돌릴 때 재사용).

## 홈 화면 빠른 동선 (2026-11-28 추가)

* **빠른 조건 칩**: 히어로 바로 아래 `총비용 1억 이하 / 1억~2억 / 2억~3억 / 3억 이상 / 월 순수익 500만↑ / 수도권`. 누르면 목록 필터(`?` 없이 화면 안에서)가 바로 걸리고, 지역·예산 선택·초기화와 같은 상태를 씁니다. 월 순수익 기준은 `profit.avg_manwon`, 수도권은 서울·경기·인천입니다.
* **지역별 점포 현황**: `data/listings.json`을 그대로 집계해 시·도별 건수(전체 139곳)를 카드로 보여 주고, 누르면 그 지역으로 목록이 좁혀집니다. 데이터가 바뀌면 자동으로 따라갑니다(하드코딩 없음).
* **공식 채널 + 양수·양도 접수 폼**: 페이지 하단 `#apply`에 네이버 블로그 3곳(에이피파트너·창업의 법칙·창업의 시선, 각 최신 글 링크)과 인스타그램·스레드, 그리고 `운영 매장 인수(양수)` / `내 매장 매각(양도)` 2갈래 폼을 두었습니다. 기본 선택은 항상 **인수(양수)** 입니다.
  - 인수(손님용, 가볍게): 희망 업종·지역·예산·브랜드(선택) + 연락처/동의 → `type:"lead"`, `source:"site"`, `form_version:"lead-gate-v1"` — 4항목 게이트와 같은 `buildLeadPayload`를 씁니다.
  - 양도(점주용, 물건표 그대로): **필수** 이름·브랜드·지역/지점명·실평수·층수·월 매출·점포 예치금·월 임차료·관리비·희망 시설·영업권·월 순수익·인건비·재료비(%)·공과금 / **선택** 오픈 시기·배달비·기타비용·**운영·시설**(영업시간·계약 기간·부가세·주차·시설 상태·최근 월별 매출)·양도 사유·희망 양도 시기·시설·운영 특이사항. 접이식 없이 처음부터 모두 보이며, 빈 칸은 오류 안내로 막습니다(해당 없으면 0). 선택 칸은 비워도 접수됩니다.
  - 양도 payload: `type:"sell_request"`, `source:"sell"`, `form_version:"sell-request-v3"`. 기존 키(`brand`·`region`·`area`·`phone`·`monthly_sales`·`key_money`·`monthly_sales_manwon`·`premium_manwon`·`contact`)를 그대로 채우고, `deposit_manwon`·`rent_manwon`·`maintenance_manwon`·`profit_manwon`·`labor_manwon`·`material_pct`·`utility_manwon`·`delivery_manwon`·`etc_manwon`·`store_pyeong`·`store_floor`·`open_ym`·`business_hours`·`lease_term`·`vat`·`parking`·`facility_state`·`monthly_sales_recent`·`sell_reason`·`sell_when`·`facility_note`를 더합니다. 텔레그램/시트로 옮겨 쓰기 쉽게 사람이 읽는 `detail_text`(줄바꿈)와 `message`(한 줄)도 함께 보냅니다. 접수는 비공개 Drive `ap-waitlist-sells.json`에 쌓입니다(예비로 `apPartnerSellRequests`에도).
  - 히어로의 `내 매장 양도 접수`·빠른 조건 옆 `양도 접수`를 누르면 이 폼으로 스크롤되며 양도 모드로 바뀝니다.

## 관리자 페이지 (`admin.html`)

* **로그인(아이디 + 비밀번호)**: 기본 최종관리자 아이디는 `hyunyul89`(김현율 · `master`)이고, 최초 비밀번호는 기존 관리자 비밀번호입니다.
  비밀번호는 **SHA-256 해시**로만 저장·검증합니다(`window.crypto.subtle.digest` + 파일로 직접 열 때를 위한 순수 JS 대체 구현). 공개 소스에 평문 비밀번호를 두지 않습니다.
  로그인 세션은 `sessionStorage`(`apAdminAuth`, 아이디·이름·역할)에 유지되고 로그아웃으로 해제됩니다. 상단 바에 현재 관리자 이름·아이디·권한이 표시됩니다.
* **이 기기에서 로그인 유지(자동 로그인, v12)**: 로그인 폼의 `이 기기에서 로그인 유지 (자동 로그인)` 체크박스(기본 체크)를 켜면 세션을 `localStorage`(`apAdminRememberSession`)에도 남겨 브라우저를 완전히 껐다 켜도 다시 로그인하지 않습니다.
  저장되는 값은 비밀번호 원문이 아니라 계정 비밀번호 해시로 만든 **세션 토큰**(+ 아이디·이름·권한·저장일·만료일 30일)이며, 비밀번호를 바꾸거나 계정을 삭제·초기화하면 토큰이 맞지 않아 자동으로 풀립니다. 마지막 로그인 아이디(`apAdminLastId`)와 체크 선택(`apAdminRememberChoice`)도 기억해 다음 로그인 때 채워 둡니다.
  헤더의 **로그아웃**을 누르면 `sessionStorage`와 `localStorage`의 자동 로그인 정보가 모두 지워집니다.
* **권한(v9)**: `master`(최종관리자)와 `consultant`(일반 컨설턴트) 두 가지입니다. 최종관리자만 **계정·권한 관리** 탭이 보이고, 컨설턴트는 매장 DB 관리 기능(등록·수정·삭제·상태 변경·CSV 일괄 등록)과 손님 DB·양도 의뢰·알림 설정을 최종관리자와 똑같이 쓸 수 있습니다. 컨설턴트 화면에는 계정 탭이 아예 렌더되지 않고, 탭을 강제로 눌러도 열리지 않으며 계정 추가·삭제·권한 변경·내보내기/불러오기 함수도 `isMaster()`로 막습니다.
* **계정·권한 관리 탭(최종관리자 전용)**: 컨설턴트 계정 추가(이름·아이디·권한·비밀번호, 기본값 `consultant`), 계정 목록(아이디·이름·권한·등록일), 권한 변경(마지막 최종관리자는 컨설턴트로 낮출 수 없음), 팀원 비밀번호 초기화(임시 비밀번호 1회 표시) / 삭제(현재 로그인 계정은 삭제 불가),
  계정 설정 JSON **내보내기/불러오기**로 다른 기기에 계정을 옮길 수 있습니다(같은 아이디는 덮어씀).
  계정은 `localStorage` `apAdminAccounts`에 해시로 저장되는 브라우저 단위 인증이므로, 실제 오픈 전에는 서버 인증으로 교체하세요.
* **내 비밀번호 변경**: 상단 바의 `내 비밀번호` 버튼으로 여는 모달에서 본인 계정만 바꿉니다(최종관리자·컨설턴트 공통).
* **비공개 지점명(v9 · 2026-11-28 갱신)**: 매장마다 `관리자 전용 비공개 지점명`을 저장해 카드 제목 옆 배지로 보여 줍니다(예: `No. AP-001` + `메가커피` + `[○○점]`).
  지점명은 `data/listings.json`·`app.js`는 물론 공개 소스 `admin.js`에도 하드코딩하지 않습니다. 관리자 로그인 직후 Apps Script `getBranches`가 비공개 Drive 폴더의 `ap-admin-branches.json`을 읽어 주고, 받은 값만 관리자 브라우저의 `localStorage`(`apAdminBranches`·`apAdminBranchInfo`)에 보관합니다.
  같은 파일의 `orig_premium`·`lnd_seq`(changupdv 원가·매물번호)는 카드에 `창업물건 참고 · 매물번호 ##### · 원가 O억 O,OOO만 원 · 게시 O억 O,OOO만 원`으로만 표시하고 손님 화면에는 내보내지 않습니다. 매장 DB 상단 `지점명·원가 새로고침` 버튼으로 다시 받을 수 있습니다.
  카드에는 손님에게 실제로 보이는 표기(`고객 노출 · 서울 ○○구 ○○ 상권` = `area`)도 함께 표시합니다.
* **담당 컨설턴트(v9)**: 매장별 `consultant_id`·`consultant_name`을 기록하고 카드에 `김현율 컨설턴트`처럼 표시합니다. 기존 12곳은 담당 지정이 없어 기본 담당 `hyunyul89`(김현율)로 보입니다. 매장 DB 상단 필터 `매장 전체 / 김현율 컨설턴트 / {추가된 컨설턴트} 컨설턴트`로 좁혀 볼 수 있습니다. 컨설턴트가 등록한 매장은 본인이 담당이 되고, 남의 매장을 수정할 때는 담당을 그대로 둡니다(최종관리자는 등록·수정 시 담당을 고를 수 있음).
* 점포를 등록·수정하면 `registered_by` · `updated_by`에 작성자(`이름 (아이디)`)를 기록하고, 카드에 표시합니다.
* **매장 DB(v9)**: 카드 목록 + `검색` · `전체 지역` · `전체 업종` · `전체 상태` · `담당 컨설턴트` 필터. 카드에 `No. AP-00x` · 브랜드 · 비공개 지점명 · 노출 상태 · 고객 노출 표기 · 초기 인수/월 매출/예상 수익/담당 컨설턴트 · 작성자, 하단에 상태 변경(노출 중/거래완료·비노출) · 수정 · 삭제.
* **매장 등록·수정**: 지역·업종·브랜드·**매장 규모(층수·평수)**·매출·예치금·권리금·**예상 월 수익 평균치**·지출(재료비 %·인건비·매장 고정비·기타잡비 만 원, 각 **평균치 한 칸**)·**특징·한줄평**·확인 포인트·공개 범위, 그리고 **관리자 전용 비공개 지점명·담당 컨설턴트**·고객 노출 미리보기.
  같은 담당 컨설턴트의 같은 비공개 지점명은 새 번호로 중복 등록하지 않고 기존 `AP-xxx`를 업데이트합니다(위 **물건표 접수 · 중복 등록 규칙**).
  매장 규모는 `층수`와 `평수` 두 칸에 나눠 넣으면 `1층 · 13평` 형태로 저장되어 카드·상세·비교표에 표시됩니다.
  `특징·한줄평`은 영업시간·주차·상권 특이사항을 자유롭게 적는 한 줄 칸이며, 매장 규모 뒤에 이어서 표시됩니다.
  지출 항목의 `매장 고정비`에는 (임대료·점포 사용료), `기타잡비`에는 (공과금·일반관리비 등)을 보조 설명으로 붙여, 공개 사이트에는 순화된 이름(`매장 고정비`, `기타잡비(공과금·일반관리비 등)`)으로만 나갑니다.
  최소·최대를 따로 적지 않고 항목마다 **평균치 하나만** 넣으면 되고, 입력하는 즉시 옆에 환산값(`약 1,088만 원`, `매출의 16.3%`)이 표시됩니다.
  저장하면 `apPartnerCatalog`에 기록되고 `index.html`이 이 목록을 우선 사용하므로 사이트에 즉시 반영됩니다.
  예상 수익은 `월 약 1,250만 원`처럼 평균임을 드러내는 표기로 저장됩니다.
  매출 범위(최소·최대) 입력칸은 없앴습니다. 예전 데이터에 매출 범위가 남아 있으면 사이트에는 그대로 `3,000~3,400만 원 범위`로 표시됩니다.
* **엑셀(CSV) 일괄 등록**: 점포 관리 탭의 **`샘플 양식(CSV) 다운로드`**로 UTF-8 BOM 양식(예시 2행)을 받아 채운 뒤,
  **`CSV 일괄 등록`** 영역에 끌어다 놓거나 파일을 고르면 업로드 전에 **행별 유효/오류 미리보기**가 열립니다.
  **`일괄 등록하기`**를 누르면 `apPartnerCatalog`에 한 번에 추가되어 사이트 목록에 바로 반영됩니다.
  - 열(17개): `고유번호` · `지역` · `업종` · `브랜드` · `층수` · `평수(평)` · `점포예치금(만원)` · `권리금(만원)` · `월평균매출(만원)` · `예상수익(만원)` · `재료비비율(%)` · `인건비(만원)` · `고정비(만원)` · `기타잡비(만원)` · `특징한줄평` · `비공개전용(Y/N)` · `비공개지점명`
  - `비공개지점명`(선택): 같은 담당 컨설턴트 안에서 같은 지점명을 찾아 **새 번호 없이 기존 매장을 업데이트**합니다. 비워 두면 신규 등록입니다. 자세한 규칙은 위의 **물건표 접수 · 중복 등록 규칙**을 보세요.
  - `고유번호`는 `AP-006`처럼 적거나 비워 두면 빈 번호 다음 번호가 자동으로 붙습니다. 이미 쓰는 번호는 새 번호로 바꿔 등록하고 미리보기에 표시합니다. 예전 15열 양식(고유번호 없음)도 그대로 읽힙니다.
  - `층수`는 `1층`·`지하 1층`처럼, `평수(평)`은 `13`처럼 숫자로 적으면 `1층 · 13평`으로 합쳐집니다. 두 칸 모두 비워도 되고, 예전 양식의 13열(`유형/브랜드`·`한줄특징` 등)도 그대로 읽힙니다.
  - `지역`은 `서울 마포구`처럼 지역과 지역구를 함께 적습니다(서울·경기·인천·대전 외 지역은 `기타`로 분류).
  - UTF-8(권장)과 EUC-KR을 모두 읽고, 따옴표·쉼표·줄바꿈이 든 칸도 처리합니다. 한 번에 300행 · 5MB까지.
  - 예전 양식의 `운영방식` 열이 남아 있어도 무시하고 안내만 표시합니다(점포 데이터에 운영 방식을 저장하지 않습니다).
  - 재료비는 매출 대비 비율(%), 인건비·매장 고정비·기타잡비는 만 원 금액으로 **평균치 하나**를 적습니다. 예전 양식처럼 `480~560` 범위로 적거나 `예상수익최소`·`예상수익최대` 두 열로 나눠 적어도 두 값의 **평균**으로 등록되고, 미리보기에 환산 결과가 표시됩니다.
    예전 양식의 `인건비비율(%)`·`고정비비율(%)`·`기타비율(%)` 열은 값이 비율로 읽혀 월 매출 기준 금액으로 환산됩니다.

## 대기 손님 조건 DB · 자동 매칭 (2026-11-28 신규)

손님 조건을 저장해 두면 새 매물이 들어왔을 때 맞는 손님을, 손님 문의가 왔을 때 맞는 매물을 바로 뽑아 주는 구조입니다.
**손님 개인정보(이름·연락처·메모)는 공개 저장소에 절대 두지 않고 비공개 Google Drive에만 저장합니다.**

### 저장 위치

| --- | --- |
| 손님 조건 DB | 비공개 Drive 폴더 `AP파트너_물건카드_비공개` 안의 `ap-waitlist-customers.json` |

### 손님 조건 필드

`id` · `name` · `phone` · `regions[]`(복수) · `categories[]` · `brands[]` · `budget_max_manwon`(총 인수 비용 상한) ·
`profit_min_manwon`(희망 최소 월 순수익) · `status`(`대기중`/`상담중`/`보류`/`계약완료`) · `memo` · `lead_id`(사이트 접수에서 등록한 경우) · 생성·수정 정보.

### 매칭 점수

* 지역: 손님 희망 지역 토큰이 매물의 지역·구·상권 설명에 모두 들어 있어야 후보(30점). 여러 곳 중 하나만 맞아도 됨.
* 업종: 매물 업종이 손님 희망 업종과 같아야 후보(25점).
* 선호 브랜드: 맞으면 15점, 아니면 후보는 유지하고 `선호 브랜드 아님` 표시.
* 예산: 총 인수 비용(점포 예치금 + 시설·영업권)이 상한 이하이면 20점, 5% 이내 초과는 8점, 그 이상 초과는 제외.
* 수익: 월 순수익이 희망 최소 이상이면 20점, 10% 이내 미달은 8점, 그 이상 미달은 제외.
* 점수는 조건별 만점 합계 대비 비율(%)로 표시하고, 같은 점수면 월 순수익이 큰 매물을 위로 올립니다.
